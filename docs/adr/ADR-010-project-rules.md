# ADR-010 项目规则不再挂在阶段上

- Status: Proposed
- Relates: FR-054, FR-048, NFR-009, MOD-04, MOD-17, EXT-03

## 背景

ADR-005 让项目通过 `harness.json` 的 `phases` 给阶段追加规则，并用 `x.` 前缀区分项目规则。阶段删除后（ADR-009），规则需要新的挂载点；PRD 的 AC-054-4 也改为用项目自己的前缀（如 `acme.01`）。

## 决策

- 项目规则在全量检查中与内置规则一起运行；登记了 `approveFor` 的规则，还会在批准该类单位时作为批准前检查运行。
- 规则编号沿用 `<区域>.<序号>`；项目前缀不得与内置规则的区域相同，由 MOD-17 在加载时校验。
- 声明式规则由独立模块 MOD-17 构造，engine 只认 IF-011。被否决的方案：放进 engine，那样 engine 要理解项目配置，扩展内置规则时就不再是封闭的。
- 本决策取代 ADR-005。内置规则的注册方式（每条规则一个文件，registry.go 中一行）不变。

## 后果

- 外部命令规则（FR-046）在 Release 3 加到 MOD-17，不改 engine。
- `x.` 前缀的旧写法仍然合法：`x` 不是内置区域。
