# ADR-009 按单位批准取代阶段

- Status: Proposed
- Relates: FR-047, FR-048, FR-037, MOD-06, MOD-11, MOD-15, FLOW-02, FLOW-08

## 背景

Release 1 按文件批准，并用线性阶段决定什么时候能写什么。到实现阶段后阶段不再前进，代理可以随时改需求和设计；改动一条需求又会让整个 PRD 的批准失效，与之无关的任务也被卡住。

## 决策

- 批准单位为一条需求、术语、待澄清项、设计元素、ADR、任务，以及每个文件中条目之外的正文（TERM-027）。哈希不含 Status 字段，PRD 正文不含变更日志。
- 批准记录放在锁文件的 `units` 中，记下批准时的内容与各上游单位的哈希。上游变化或失效时下游失效，并能说出是哪个上游引起的。
- 批准时内容写入锁文件，`harness approve` 据此显示差异。被否决的方案：从 git 历史取上次批准时的内容。批准与提交不一一对应，按提交查找既慢又会出错。
- 删除阶段。产物任何时候都可写；能否开工由任务的批准链决定，门禁在源码写入时检查。
- 被否决的方案：保留阶段，增加"退回"命令。退回仍以整个阶段为粒度，解决不了一条需求变化牵连全部任务的问题。
- 本决策取代 ADR-004 中关于当前阶段与按文件批准的部分；锁文件的其余约定（受保护、键排序、只由 harness 命令写入）不变。

## 后果

- 锁文件变大：大约是全部产物文本的规范化副本。
- 门禁写源码时需要计算一条批准链，只算当前 InProgress 任务这一条。
- Release 1 的锁文件由 `harness lock` 一次性迁移；MOD-10、EXT-04 在 `Current-Release` 改为 2 时删除。
