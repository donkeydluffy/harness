# ADR-018 批准等待正在执行的代理命令，恢复前另存

- Status: Proposed
- Relates: FR-056, MOD-02, MOD-11

## 背景

门禁在代理命令执行前记录文件状态，命令结束后把不允许的改动恢复为命令前的内容（ADR-003）。锁文件受保护，代理命令执行期间锁文件的任何变化都会被恢复。人在自己的终端执行 `harness approve` 时，如果代理的长命令（如 `harness check unit`）正在执行，人写入的批准记录在命令结束后被恢复掉，而且没有提示（DEBT-021，2026-11-27 一次丢失 62 个单位的批准）。

## 决策

- `harness approve` 在列出待批准单位前检查 `.harness/snap/` 下是否有未被清除的命令前快照；有就提示人并等待它消失，写入锁文件前再检查一次。快照早于 10 分钟前时视为代理异常退出留下的残留，询问人是否继续。
- 命令后比对恢复或删除任何文件前，把文件当前内容另存到 `.harness/session/restored/<时间>/<路径>`，恢复报告列出另存位置。该目录已被 `.harness/.gitignore` 忽略，也在门禁的保护目录内，代理不能改动另存的内容。
- 被否决的方案：命令后比对放行锁文件中时间晚于命令开始的批准记录。代理可以自己写出带有更晚时间的批准记录，锁文件的保护就失效了。
- 被否决的方案：另存到新目录 `.harness/restored/`。需要修改 init 生成的 `.harness/.gitignore`，已初始化的项目不会更新（DEBT-018）。

## 后果

- 批准与代理命令不再互相覆盖；代理命令很长时，人要等它结束才能批准。
- 写入前的复查与写入之间仍有极短的窗口：这期间开始的代理命令会把锁文件恢复，但内容已另存，人可以从另存位置复制回去。
- 另存目录不自动清理，大小随恢复次数增长；大于 1 MiB 的文件本来就不恢复，也不另存。
